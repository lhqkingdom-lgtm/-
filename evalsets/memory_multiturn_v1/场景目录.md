# 多轮长期记忆评测场景目录

## 当前发布门禁（9 个）

### 1. 风扇阈值附近反复启停，修复后用户确认

- 来源：当前真实 CP 会话，3 个 turn。
- 流程：上板现象 → 定位并增加连续采样/时间滤波 → 用户重新烧录确认。
- 应有结果：最后只产生 1 条运行经验，完整包含现象、原因、修复、用户验证。
- 关键失败：在用户确认前写正式记忆，或只记录“加滤波”而丢失触发条件和验证。

### 2. 光感链中插入雷达问题和一次性任务边界

- 来源：同事 EL48 真实会话，4 个 turn。
- 流程：光感无效并尝试修复 → 雷达修复仍失败 → 本次只改指定模块 → 用户确认光感恢复。
- 应有结果：最终只闭环光感链；根因为物理 ADC 通道与寄存器编码偏移，修正后用户确认。
- 关键失败：把雷达问题并入光感记忆，或把“只改指定模块”误存为长期偏好。

### 3. 云编译选错工程，修正入口后完整编译通过

- 来源：同事 FL20Pro 真实会话，2 个 turn。
- 流程：本地受版本限制、云端只构建子集 → 用户纠正能力判断 → 定位多个 uvproj 干扰工程检测 → 完整编译通过。
- 应有结果：1 条编译失败经验，覆盖失败、根因、修复和完整编译验证。
- 关键失败：第一次部分构建后就沉淀，或把具体 HEX 路径存入记忆。

### 4. 雷达修复被用户否定

- 来源：同事 EL48 真实会话，2 个 turn。
- 流程：助手实施修复 → 用户反馈仍无法被开关键打断。
- 应有结果：原运行故障链进入 `fix_rejected`，正式记忆数为 0。
- 关键失败：把被否定的修复写成有效经验，或重复新建故障链。

### 5. FL20 多次修复但没有最终用户确认

- 来源：同事 FL20Pro 真实会话，4 个 turn。
- 流程：多项上板异常 → 第二次仍有失败 → 新现象/先定位 → 再次修复并编译、等待复测。
- 应有结果：链保持未闭环，正式记忆数为 0。
- 关键失败：用最后一次“编译通过”替代用户上板确认，或把多项未闭环现象拆成正式记忆。

### 6. 跨项目重复表达“信息不足先问，不要猜”（夹带未闭环编译失败）

- 来源：同事 3 个真实项目会话，各取 1 个 turn。
- 流程：首次明确偏好 → 其他项目重复表达 → 第三个项目再次印证；第三个长 turn 同时包含 Keil 工具 Fatal Exit Code 3、直接本地命令构建成功和云构建成功。
- 应有结果：最终只有 1 条用户偏好；重复证据用于增强、合并或保持，不产生三条副本。
- 编译侧期望：错误码只有通用释义，同一环境又能通过其他调用入口构建，尚未定位两种调用的关键差异；可记录 `failure_observed` 未闭环链，但不能创建“本地许可证/环境坏了，换云端即可”的正式编译经验。
- 关键失败：保存具体 SDK 路径、IO 数值、每次重复新建，或把工具通用报错解释升级为已证实根因。

### 7. 本次代码提交为 v1

- 来源：同事真实会话，1 个 turn。
- 应有结果：`noop`。
- 原因：只表达“本次”，没有“以后/每次”或跨项目重复证据。
- 关键失败：推断“用户总是希望关键版本进 Git”。

### 8. 低价值 turn 过滤

- 来源：同事真实会话，5 个 turn。
- 内容：继续、文件位置、一次性文件转换、带助手转述的 HEX 位置问题、数据库位置。
- 应有结果：全部 `noop`，正式记忆数为 0。
- 关键失败：把路径、一次性操作或缺乏直接证据的助手转述升级为长期记忆。

### 9. 编译/烧录修复后仍失败

- 真实现象：调整代码区后用户仍报告相同“程序过大”问题。
- 验收结果：首轮保持 `fix_applied`，因为编译 0 Error 不能证明原烧录错误消失；用户否定后复用同一 `chain_id` 进入 `fix_rejected`。
- 应有结果：两轮均 `noop`，正式记忆数为 0；`transition_history` 保留完整迁移，`rejected_attempt_count=1`。
- 关键失败：把上游编译通过误当成原烧录错误已解决，或在用户否定后重复新建故障链。

## 已知缺口观察（1 个，不计当前发布门禁）

### 10. 同一 turn 同时确认旧问题和报告新问题

- 真实现象：用户确认按键与 LED 已对应，同时报告物理位置仍不符合预期。
- 规范期望：关闭旧链并沉淀旧经验，同时新开另一条未闭环链。
- 当前缺口：最终决策只有一个顶层 `chain_state`，不能在同一 turn 完成两个链动作。

## 人工验收时重点看什么

1. 技术链闭环前是否始终没有正式记忆写入。
2. 最后一轮是否真的读取了所需历史 turn，而不是只看摘要猜测。
3. 闭环记忆是否包含现象、原因、修复、验证四项。
4. 插入的无关 turn 是否没有污染故障链。
5. 同一故障是否只形成一条记忆，同一偏好是否没有重复副本。
6. 记忆是否抽象为相似任务可复用规则，同时保留必要适用范围。
