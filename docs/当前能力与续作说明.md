# Memory Lab 当前能力与续作说明

本文用于在另一台电脑继续开发时快速恢复上下文。它只记录当前已经落地的代码能力、已验证结果、尚未完成的问题和启动方式。

## 1. 当前目标

系统从 CodePulse 的真实开发对话中沉淀三类长期记忆：

1. `user_preference`：稳定的用户协作习惯和关键纠正。
2. `compile_failure_experience`：编译、链接、构建和烧录前失败经验。
3. `runtime_failure_experience`：烧录后现象、根因、解决方法和验证结果。

需求文档保存当前项目规格；长期记忆只保存以后能减少重复问答、错误和返工的信息。

## 2. 当前整体链路

```text
CP SQLite 原始会话（只读）
  → 增量读取消息和工具事件
  → 按一轮任务切分 turn
  → 生成 core / candidate / pointer 三层证据池
  → 将 turn 和证据写入 PostgreSQL
  → ReAct 记忆 Agent 读取当前证据和已有 topic/memory 摘要
  → 必要时调用只读工具补查详情、历史、冲突或原始 pointer
  → 输出 memory-changes-v1 结构化计划
  → 本地程序校验类型、ID、证据权限、幂等和事务边界
  → 提交 memory/topic/revision/conflict 或明确 noop
  → 输出中文终端日志和可审计报告
```

模型不直接操作数据库。模型只输出计划，所有正式写入均由本地工具校验后执行。

## 3. 评测集

位置：

```text
evalsets/memory_eval_v1/
├── cases.jsonl
├── scenarios.json
├── README.md
└── sources.md
```

当前包含：

- 40 条真实单 turn 用例；
- 7 组连续多 turn 场景；
- 数据主要来自同事真实 CP SQLite；
- 每条 case 保存 source/session/turn 标识、允许/禁止动作、应提取/不应提取信息、期望类型、范围、状态和过程要求。

单 turn 隔离回放用于判断“这一轮是否值得沉淀、结果是否有用”。连续场景用于判断“相似信息能否更新/合并、用户确认后能否补充验证状态”。

评测标准冻结原则：

- 不因单次模型输出失败而修改答案；
- 修改标准前必须回看原始 turn 和处理过程；
- 功能变化后重跑同一评测集，保证前后结果可比较；
- 仅修改评测说明时可以重判已有报告，不必重新调用模型。

## 4. 评测链路

入口：

```powershell
.\memory-lab.ps1 eval-memory
```

支持模式：

| 模式 | 作用 |
|---|---|
| `plan` | 校验评测集、turn 和数据源是否完整，不调用模型 |
| `single-batch` | 多条单 turn 使用同一评测用户空间 |
| `single-isolated` | 每条 case 使用独立用户空间，避免互相污染 |
| `scenario-sequential` | 同一场景按顺序处理多个 turn，验证 create/update/merge |
| `review-existing` | 使用最新评测标准重判已有报告，不重跑主链路 |

完整冻结单 turn 回放示例：

```powershell
.\memory-lab.ps1 eval-memory `
  -SourceDatabase "D:\opencode-dev\opencode-dev.db" `
  -LabDatabase ".\data\eval\memory_eval_index.db" `
  -PgConfigPath ".\pg-memory-lab.local.json" `
  -EvalSetPath ".\evalsets\memory_eval_v1" `
  -EvalMode single-isolated `
  -RunName "stage1-frozen-quality-baseline" `
  -Limit 40 `
  -MaxIterations 3
```

评测输出位于 `reports/eval/`，包括：

- `eval-detail.json`：每条 turn 的动作、证据和最终计划；
- `eval-summary.md`：执行与动作结果；
- `generated-memories.md`：本轮全部记忆；
- `quality-report.md`：规则型质量初筛；
- `quality-report-rejudged.md`：使用最新评测字段重判后的报告；
- `react-logs/`：逐条 ReAct 调用日志；
- `runs/`：每条隔离 case 的配置与结果。

`reports/` 是本地产物并被 Git 忽略；需要对比时应在本机保留或单独打包。

## 5. 最新冻结基线

最新完整回放使用当前 40 条冻结单 turn：

| 指标 | 结果 |
|---|---:|
| 执行成功率 | 40/40，100% |
| 证据包存在率 | 34/34，100% |
| 已有记忆检查率 | 40/40，100% |
| 决策理由存在率 | 40/40，100% |
| 动作命中率 | 38/40，95% |
| 必须写入用例召回 | 18/20，90% |
| 明确 noop 用例命中 | 11/11，100% |
| 精确 stable_key 重复 | 0 |

人工审查本轮 36 条新增记忆：

- 27 条可直接复用（75%）；
- 8 条包含有用信息，但需要拆分、去重或收紧表达；
- 1 条不应沉淀。

当前结论：候选记忆生成已经可用，但还不适合无人审核地长期自动积累。

主要质量问题：

1. 长 turn 中可能抓错重点，部分重要用户现象没有进入最终记忆。
2. 不同根因可能为了控制数量被强行合并。
3. 临时测试参数或当前产品需求可能被包装成长期经验。
4. 同一 turn 内可能产生语义重叠、stable_key 不同的记忆。

## 6. 自动入口链路

### 6.1 单次处理

```powershell
.\memory-lab.ps1 process-new-turns `
  -SourceDatabase "$env:USERPROFILE\.local\share\codepulse\opencode-dev.db" `
  -PgConfigPath .\pg-memory-lab.local.json `
  -Limit 3 `
  -AgentLogDirectory .\reports\poll-new-turns-live
```

### 6.2 持续轮询

```powershell
.\memory-lab.ps1 poll-new-turns `
  -SourceDatabase "$env:USERPROFILE\.local\share\codepulse\opencode-dev.db" `
  -PgConfigPath .\pg-memory-lab.local.json `
  -Limit 3 `
  -AgentLogDirectory .\reports\poll-new-turns-live `
  -IntervalSeconds 20
```

当前行为：

- 每轮先增量读取 CP SQLite；
- 扫描稳定完成/失败的 turn；
- 已成功处理的 turn 自动跳过；
- 每批最多处理 `Limit` 条；
- 待处理 turn 按时间从旧到新执行，避免新 turn 长期挤压旧 turn；
- `-DryRun` 只运行判断和日志，不提交 memory；
- `-Reprocess` 可用于评测时重新处理已完成 turn，不应在正常长期轮询中使用。

当前入口适合单机、单个 Memory Lab 进程。多设备或多个轮询进程同时写入的租约、抢占和并发隔离尚未完成。

## 10. 下一步顺序

继续完善时按以下顺序推进，不修改冻结评测集来迎合模型结果：

1. 增加重要证据覆盖清单，保证长 turn 的每个关键问题都被判断为 store/noop/need_more_evidence。
2. 删除颗粒度规则冲突：同根因同方案合并，不同根因或不同方案拆分；数量不是判断依据。
3. 收紧三种类型准入，禁止把临时测试参数和当前产品功能强塞进运行失败经验。
4. 增加同一 turn 内的语义去重自检。
5. 使用同一冻结 40 条做定向回归和完整回归，目标是直接可复用率达到 90% 以上。
6. 单 turn 质量稳定后，运行 7 组连续场景，验证 update/merge/验证状态补全。
7. 再推进记忆召回、CP主流程注入和多窗口/多设备并发。

近期不要优先修改数据库表或增加第二个评审模型；当前瓶颈主要位于证据覆盖、准入边界和记忆颗粒度。
